# B 站转发流程选择器改造设计

## 目标

适配当前 B 站动态详情页结构，让单条动态转发流程能完成登录校验、关注、点赞、评论和转发。

## 当前问题

- `login_by_cookie()` 写死了已过期的 `expiry`，浏览器会丢弃 Cookie。
- `login_by_cookie()` 没有校验登录状态，只要没有异常就打印登录成功。
- `share_one_dynamic.py` 仍依赖旧版固定层级 XPath。
- 转发测试失败在 `click_follow()`，当前页面已经找不到旧的关注区域 XPath。

## 实现方案

### 登录

- 添加 Cookie 时不再写死过期时间。
- 支持同时注入 `SESSDATA` 和 `bili_jct`。
- 执行评论/转发前必须存在 `bili_jct` Cookie，缺失时停止执行，避免 B 站接口 `csrf` 为空导致假成功。
- 登录后通过当前页面的头部登录入口、动态页评论区提示等页面状态判断是否成功。
- 登录失败时抛出异常，避免继续执行关注、评论和转发。

### 转发详情页

- 继续使用 Selenium 打开单条动态链接。
- 不再强制切换旧版页面。
- 作者信息从当前动态卡片结构读取：
  - `.bili-dyn-title`
  - `.bili-rich-text-module.at`
  - 动态页中的 `space.bilibili.com/<uid>` 链接
- 关注按钮优先使用当前结构：
  - `.dyn-orig-author__following`
  - 文本为 `关注` 的按钮或可点击元素
- 点赞、评论、转发优先使用当前语义 class 和文本：
  - `.bili-dyn-action.like`
  - 评论输入框 `textarea` 或可编辑输入区
  - `.bili-dyn-action.forward`
  - 弹窗中的输入区和发布/转发按钮
- 转发编辑器使用 Selenium `send_keys()` 输入，触发 B 站富文本组件的真实输入事件。
- 点击发布后必须等待“发布成功/转发成功”提示或转发弹窗关闭，才回写成功状态。

### 过期动态跳过

- 转发前先读取当前动态正文、原动态正文和转发弹窗可见文本。
- 从文本中解析抽奖截止/开奖日期，支持 `9月4日`、`9.4`、`9/4`、`2026年9月4日` 等常见写法。
- 只在解析出的最大日期早于当天时判断为过期。
- 日期为当天时不跳过，解析不到日期时不跳过，降低误判。
- 过期动态不执行关注、点赞、评论、转发。
- 过期动态使用 `t_draw_dynamic.status=2` 标记，避免后续重复处理。

## 失败策略

- 找不到可选的预约按钮时跳过。
- 解析到过期动态时跳过，不计入转发成功。
- 缺少 `bili_jct` 时抛出异常并保持 `share_status=1`。
- 点击发布后没有成功反馈时抛出异常并保持 `share_status=1`。
- 找不到必需的登录态、评论框或转发按钮时抛出异常并保持 `share_status=1`。
- 单条失败不回写成功状态。

## 验证标准

- Python 编译通过。
- Docker 构建通过。
- 登录后页面不再显示未登录评论提示。
- 单条真实转发测试成功时 `share_status=0` 并回写数据库。
- 过期动态测试能回写 `status=2`，且不发布评论或转发。
- 单条真实转发测试失败时日志能定位到具体步骤。
